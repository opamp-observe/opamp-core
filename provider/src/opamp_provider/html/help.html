This console monitors connected agents, highlights late communications, and lets you queue commands or staged configurations.

  • Amber rows are past the delayed comms threshold.
  • Red rows are past the significant comms threshold.
  • Rows with pending config or commands show a colored border (pending indicator).
  • The pending indicator means the server has queued a change for that agent but has not yet sent it.
  • Until a client reports service.instance.id, the UI uses the OpAMP unique ID (instance_uid) as the service instance name/display ID.
  • Disconnected status means the agent explicitly sent an OpAMP disconnect message and will be purged after the configured retention period.
  • Disconnected agents are excluded from late/overdue counts and are tinted electric blue in the table.

Server Console Filters

The client table includes an inline filter row directly beneath the column headings.

  • Text filters: Service Instance ID, Instance UID, Client Version, Host Name, and Host IP use case-insensitive substring matching.
  • No wildcard characters are needed: entering alpha matches svc-alpha-01.
  • Exclude mode: add invertFilter=true on filter requests to invert the active filter set and exclude matching rows.
  • Multi-select filters: Connection Status, Health Status, Config Version, Host Type, and Host Version provide dropdown menus with the values currently present in the table data.
  • Combined filters: Filters are combined with AND, so a row must satisfy every populated column filter.
  • Inline workflow: Filtering updates the table immediately without separate show, hide, apply, or clear controls.
  • Personalization persistence: UI personalization for column order and optional column visibility is cached in browser cookies so your layout is restored in later sessions.

Additional Display Columns

Use Show Columns on the main page to enable optional columns in the client table. These columns are hidden by default and can be shown or hidden independently.

  • Health Status: Provider health summary using the same healthy, unhealthy, or unknown color coding shown in the agent summary.
  • First Registered: First time the provider recorded the client connecting.
  • Client Version: Client-reported version value.
  • Host Type: Host operating system type (for example from os_type).
  • Host Version: Host operating system version (for example from os_version).
  • Host Name: Hostname when reported by the client.
  • Host IP: Reported host IP address (falls back to the source/remote address when available).
  • Reorder: Drag and drop table headers to change column order.
  • Persistence: Selected columns and column order are restored automatically from browser cookies.

Embedded Feature Pages

When the provider hosts embedded tools such as Config Editor or Config Catalog, their headers include navigation helpers.

  • Server Console: Returns directly to the provider UI.
  • Back: Uses the browser-history back action and is shown only when a back-navigation target is available.
  • Standalone mode: These buttons stay hidden when the tools are deployed independently of the provider.

Main Page Right-Click Options

On the main client table, right-click a client row to open the context menu.

  • Remove Client: Removes that client record from provider memory.
  • Issue New Unique ID: Requests a new OpAMP instance UID for that client.

Configuration Tab Remote Files

When provider.allow-remote-config is enabled, the client Configuration tab includes a remote file workflow in addition to the existing requested-config text area.

  • Requested Configuration: Becomes read-only when Config Editor is available from the Feature menu.
  • Availability: The remote file panel appears only when provider remote-config support is enabled.
  • Select Configs: Appears only when the catalog feature is available in this deployment.
  • Popup selection: The catalog opens in a popup, and checkbox selection order is preserved when files are returned.
  • Drag reorder and remove: Selected files can be dragged into a new order or removed before sending.
  • Separate send step: Choosing files does not queue them automatically. Use Send Remote Config Files to submit the selected list.
  • Capability note: The provider still validates agent remote-config support when the send request is queued.

Global Settings Overview

Use the Global Settings button in the main header to open provider-wide settings. The dialog has two tabs: Server Settings and Client Settings.

  • Server Settings tab: Communication thresholds, human approval mode, and state persistence controls.
  • Client Settings tab: Default client heartbeat frequency and client event-history size.

Global Settings Save Actions

  • OK: Applies changes from the active tab to live provider settings.
  • OK + Save: Applies server settings and persists them to opamp.json.
  • Save State Now: Forces an immediate persisted state snapshot write using current state-persistence settings.
  • Cancel: Closes the dialog without applying pending edits.

Note: Whether a client permanently stores heartbeat-related changes is client-specific behavior. The server can request/track heartbeat settings, but client-side persistence across restarts depends on the client implementation.

State Restore and Snapshots

  • Enable persistence: Set provider.state_persistence.enabled=true in Global Settings (Server tab) or in opamp.json, and configure state_file_prefix.
  • Snapshot naming: Each save writes a new UTC timestamped file, for example runtime/opamp_server_state.20260409T103000Z.json.
  • Retention: The provider keeps the newest snapshots using retention_count (default 5).
  • Auto restore: Start with --restore to load the latest snapshot for the configured prefix.
  • Explicit restore: Start with --restore <snapshot_file> to restore from a specific file.
  • Diagnostic mode: Start with --diagnostic to enable the diagnostic config viewer tab and other local troubleshooting endpoints.
  • Restore fallback behavior: If restore fails (missing/corrupt/incompatible file), provider logs the error and continues startup with an empty/default in-memory state.

Use the main page to open an agent, paste config/commands, and save. Changes are queued until the next agent check-in.

Feature Menu

The main UI header can show a Feature dropdown when optional component endpoints are configured.

  • Config Editor: Opens embedded config-service editor when configured via component-entry-points.quart.
  • Config Catalog: Opens provider catalog view when opamp.config_catalog.enabled=true.
  • Catalog help: /catalog/help (available when catalog feature is enabled).
